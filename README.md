# claude-log-viewer

Claude Code のセッションを、ブラウザから探して読み、そのまま続きを動かすためのローカルサーバーです。

> [!NOTE]
> ターミナルで動いているセッションの許可の確認にビュワーで答える機能（試験中）は、既定ではオフです。使うには `npm run setup-hook -- --run` で `~/.claude/settings.json` に hook を登録し、設定画面の「承認」でオンにします。手順は「[ターミナルの許可の確認に答える](#ターミナルの許可の確認に答える試験中)」にあります。

- **探して読む**：会話ログ（`~/.claude/projects` の JSONL）をまとめて全文検索し、どの Issue・PR・リポジトリ・ファイルを扱ったセッションかで絞り込めます。長いセッションや「あれはどのセッションだったか」を探しやすくなります
- **続きを動かす**：開いたセッションに続きを送ったり、新しいセッションを始めたりできます。Claude からの質問や許可の確認にもブラウザで答えられ、入力欄の上にはターミナルと同じステータスラインが出ます
- **並べて見張る**：一覧の各セッションに、作業中・確認待ち・未読などの印が tmux のタブと同じ色で付き、OS の通知を押すとその返事まで飛べます。作業を眺めながら、次に送るプロンプトをメモ欄に書いておけます

依存パッケージはありません。

## 起動

Node.js 20 以上が必要です（動作確認は Node.js 24）。

```sh
git clone https://github.com/Marco3jp/claude-log-viewer.git
cd claude-log-viewer
npm start
```

http://127.0.0.1:4317/ を開きます。

| 環境変数 | 既定値 | 内容 |
|---|---|---|
| `PORT` | `4317` | 待ち受けるポート |
| `CLAUDE_PROJECTS_DIR` | `~/.claude/projects` | 会話ログを読むディレクトリ |
| `CLAUDE_LOG_VIEWER_DATA` | `~/.local/share/claude-log-viewer` | ブックマーク・非表示にしたセッション・メモ・ビュワーで付けたタイトル・ステータスラインと非表示の設定の保存先（`XDG_DATA_HOME` があればその下） |
| `CLAUDE_BIN` | `claude` | 続きを送るときに起動する Claude Code のコマンド |
| `TMUX_SOCKET_NAME` | （普段の tmux サーバー） | ターミナルの tmux で開いているセッションに送るときの tmux サーバー（`tmux -L` に渡す名前） |
| `CLAUDE_LOG_VIEWER_PORT` | `4317` | hook のスクリプトがつなぐポート。`PORT` を変えたときに hook 側に設定する |

## できること

### セッションを探す

- 左の検索欄で全文検索します。スペース区切りで AND、`"…"` でフレーズ、先頭に `-` で除外です
- 検索の対象は、ユーザーの発言・Claude の返答・思考・ツールの入力と結果（先頭 4,000 字）・サブエージェントのやり取りです
- 「詳細検索」を開くと、次の条件で絞り込めます。候補には件数が出て、クリックすると条件に加わります
  - リポジトリ（作業ディレクトリの `.git/config` から GitHub の `owner/repo` を出します）
  - Issue・PR（GitHub の URL、`gh pr view 123` などのコマンド、Claude Code が記録した PR のリンクから拾います）
  - 読み書きしたファイル・ディレクトリ（パスの一部で指定し、読んだ・書いたを選べます）
  - 期間、プロジェクト、ブランチ、使ったツール、MCP サーバー、ブックマーク
- 条件は URL に入るので、ブラウザのブックマークでも同じ検索を開き直せます
- 一覧のタイトルは、ビュワーで付けたタイトル・`/rename` などで付けたタイトル・AI が付けたタイトル・最初のプロンプトのうち、先にあるものを出します
- ★ でブックマークしたセッションは、並び順によらず一覧の上に固めて出します。ブックマークしたものの中は、選んだ並び順のままです
- `/usage` のようなローカルコマンドだけで Claude の返答が無いセッションは、既定では一覧に出しません（「一覧から隠す」を参照）

### 一覧から隠す

- 一覧の行にマウスを載せると、右に「隠す」が出ます。押すとそのセッションを一覧から隠します
- 設定画面の「非表示」で、次の条件に当たるセッションをまとめて隠せます。文字列は 1 行に 1 つずつ書き、大文字と小文字は区別しません
  - 返答の無いセッション：`/usage` のようなローカルコマンドだけで、Claude の返答が無いもの。既定で隠します
  - タイトルに含まれていたら隠す：一覧に出るタイトル（無ければ最初のプロンプト）だけを見ます
  - タイトルか本文のどこかに含まれていたら隠す：全文検索と同じ範囲を見ます
  - 作業ディレクトリがこの下にあったら隠す：セッションを始めたディレクトリを見ます。`/` か `~` から書きます。定期実行のタスクのように `/private/var/folders` の下で動くものをまとめて隠すときに使います。macOS の `/private/var` と `/var` は同じ場所として扱います
- 隠したセッションはミュートとして扱い、返事が来ても確認待ちになっても OS の通知を出しません。理由（「隠す」・返答なし・条件）によらず同じです
- 「隠す」で隠したセッションは、設定画面の「非表示」の下に新しく隠した順で並び、「戻す」で一覧に戻せます。タイトルを押すとそのセッションを開きます
- 隠したセッションは、詳細検索の「非表示にしたセッションも出す」で薄く出ます。「隠す」で隠したものは行の「戻す」で戻せます。返答が無くて隠れているものには「返答なし」、文字列やディレクトリで隠れているものには「条件」と出るので、設定画面の「非表示」を変えてください
- 隠したセッションと条件は、サーバーのデータ用ディレクトリに保存します

### セッションを読む

- セッションは末尾（一番新しいところ）で開きます。通知から開いたときはその返事、未読があれば前に読んだところより後の最初の行、検索語があれば最初の一致で開きます
- ヘッダーに `claude --resume <id>` のコピーボタン、関わった Issue・PR、読み書きしたファイルの一覧が出ます
  - Issue・PR は、このセッションで出したもの（「出した」）、最初のプロンプトにあったもの（「依頼元」）、それ以外に分けて出します。詳細検索の結果のバッジも同じ順に並べ、「出した」「依頼元」を付けます
  - 出したものは、Claude Code が記録した PR のリンクと、`gh pr create`・`gh issue create` の結果に出た URL から拾います
- ヘッダーのタイトルの右の「書き換える」でタイトルを変えられます。「AI で付け直す」を押すと、会話の中身（最初の依頼と後ろのほうのやり取り）から haiku にタイトルを付け直させます。Issue 番号だけの、何をしたか分からないタイトルを直すときに使います
  - ビュワーで付けたタイトルは、データ用ディレクトリの `titles.json` に保存します。Claude Code の会話ログには書かないので、`claude --resume` の一覧のタイトルは変わりません
  - 「元に戻す」で、Claude Code が付けたタイトルに戻します
- Bash の `cd` で作業ディレクトリが移ったところには、会話の中に移った先を挟みます（Bash を隠すと一緒に隠れます）。始めたディレクトリから移っているときは、ヘッダーの「場所」と入力欄の上に、最後にいたディレクトリを出します
- 思考・Bash・ツール・MCP・サブエージェント・システムを、種類ごとに表示・非表示できます
- セッション内検索で、一致した箇所へ前後に移動できます。非表示にしている種類の中の一致は件数だけ出ます
- 右端のメモ欄に、セッションごとのメモを書けます。作業を眺めながら次に送るプロンプトを書いておく場所です。書いた内容は自動で保存し、「入力欄へ」で選択した部分（選択が無ければ全部）を送信の入力欄に写せます
- Claude の返答は Markdown として表示します。表は等幅フォントです
- サブエージェントの呼び出しを開くと、その中のやり取りをその場に展開できます。動いている途中のものも開けて、書き足されると開いたまま読み直します
- 会話ログが書き足されると、2 秒ほどで一覧と表示中のセッションが読み直されます。読んでいた位置は保ち、末尾を見ていたときは末尾に付いていきます。タブが裏にある間は止まり、表に戻したときに読み直します
- ★ でセッションをブックマークできます
- 一覧・ヘッダー・メモは、境目のドラッグで大きさを変えられます。ボタンで畳めて、ダブルクリックで元の大きさに戻ります

### 続きを送る

- セッションの下の入力欄から、そのセッションに続きのメッセージを送れます。既定では `Enter` で送信、`Shift+Enter` で改行で、キー操作の設定で変えられます
- 送信してから Claude に渡すまで、既定では 2 秒待ちます。その間は会話の末尾に仮の吹き出しが出て、「取り消す」か `Esc` で取り消せます。取り消した文面は入力欄に戻ります。待つ秒数は設定画面の「送信」で変えられ、0 にするとすぐ送ります。送ったあとも、会話ログに書かれるまでは「送信済み・反映待ち」の吹き出しを出します
  - 送信待ちの間にほかのセッションへ移っても、そのまま送ります。移った先のセッションからも続けて送れます。送れなかったときは、文面をそのセッションの入力欄に戻し、そのセッションを開いたときに理由を出します
- 入力欄の先頭で `/` を打つとコマンドとスキル、空白の後ろで `@` を打つとファイルとディレクトリの候補が出ます。上下で選び、`Enter` か `Tab` で入れ、`Esc` で閉じます
  - コマンドの候補は、ビュワーがそのディレクトリで `claude` を起動したときに受け取った一覧です（組み込みのコマンドとプラグインのものも入ります）。まだ起動していないディレクトリでは、`~/.claude` とプロジェクトの `.claude` の `commands`・`skills` から拾います
  - ファイルの候補は、セッションを始めたディレクトリの `git ls-files` から出します。git の外では、`node_modules` などを飛ばしてディレクトリをたどります
- サーバーがセッションの作業ディレクトリで `claude -p --resume <id>` を起動し、会話ログに書き足された分がそのまま表示されます。プロセスは 10 分使わなければ止まります
- 入力欄の右に、状態（待機中・作業中・確認待ち）と権限モード、「送信」「止める」をいつも出します。「止める」は作業中か確認待ちのときだけ押せて、続けて 2 回押すと、Claude Code で `Esc` を押したときと同じくその回の作業を打ち切ります。会話とプロセスはそのまま残るので、続けて送れます
- 権限モードは、そのセッションをターミナルで最後に使ったときのもの（`auto`・`acceptEdits`・`plan`・`dontAsk`）を引き継ぎます。ビュワーで始めたセッションは、ビュワーで選んだモードを引き継ぎます。`bypassPermissions` は引き継がず、確認を出すモードで動かします
- Claude からの質問（AskUserQuestion）と、ツールや MCP を使う前の許可の確認は、入力欄の上にカードで出ます。選択肢を選ぶ・許可する・理由を添えて拒否する、をそこで答えます。許可の確認には、Bash なら説明とコマンド、Edit なら変更前と変更後のように、ツールごとに中身を分けて出します
- ターミナルなど別のプロセスで開いているセッションには、ビュワーから `claude` を起動して送ることはしません。同じセッションを 2 つのプロセスが別々に動かすと、会話が分かれたり、お互いのやり取りが見えなかったりするためです
- そのセッションがターミナルの tmux の中で開かれていれば、tmux のキー入力として送れます（試験中）。入力欄が黄色になり、送った文はターミナルの入力欄に貼り付けて送ります。ターミナルで打ったのと同じ、ユーザーの発言として届きます
  - 送る前に tmux の画面を読み、ターミナルの入力欄に書きかけの文があるときと、選択肢などが出ていて入力欄が見つからないときは送りません。そのときは理由と画面の下のほうを出します
  - 送る先のペインで動いているのがそのセッションの `claude` か、プロセスの親子関係で確かめてから送ります
  - 確認や質問にはターミナルで答えます。「止める」も使えません
- ビュワーから動かしている `claude` はサーバーの子プロセスなので、サーバーを止めると一緒に止まります。`Ctrl+C` の 1 回目は、作業中・確認待ちのセッションがあればターミナルにその名前を出し、終わるのを待ってから止めます（待っている間は新しい送信を断ります）。2 回目の `Ctrl+C` で、待たずに止めます。ターミナルで動かしている `claude` には影響しません
- POST はこのビュワーのページから来たもの（`Origin` が `http://127.0.0.1:<PORT>` か `http://localhost:<PORT>`）だけを受けます

### 新しく始める

- 左上の「新規チャット」で、作業ディレクトリ・権限モード・最初のメッセージを入れて新しいセッションを始められます
- 作業ディレクトリの候補には、最近のセッションで使ったディレクトリが出ます。開いているセッションがあれば、その作業ディレクトリが初めから入ります
- 会話ログが書かれ始めると、そのセッションが開きます。そこからは「続きを送る」と同じように使えます
- `claude -p` はターミナルの `claude` と違ってタイトルを自動で付けないので、ビュワーが最初のメッセージから付けるよう頼みます。タイトルの無いセッションに続きを送ったときも、そのセッションの最初のプロンプトから付けてもらいます

### ターミナルの許可の確認に答える（試験中）

ターミナルで動いているセッションの許可の確認を、Claude Code の `PermissionRequest` hook からビュワーに送ります。ビュワーは中身を調べてそのセッションの入力欄の上に出し、人の答えを待ちます。設定でオンにすれば、読むだけのものは自動で許可します。

既定ではオフです。使うときは次の順に設定します。

1. `npm run setup-hook -- --dry-run` を実行し、`~/.claude/settings.json` の `hooks.PermissionRequest` がどう変わるかを見る
2. `npm run setup-hook -- --run` を実行して hook を登録する（元のファイルは `settings.json.bak` に残ります）
3. 設定画面の「承認」で「hook から届いた確認を受け付ける」をオンにして保存する
4. 自動で許可したいときは、「下の条件に当たらないものは自動で許可する」もオンにして保存する

- ビュワーを `PORT` や `CLAUDE_LOG_VIEWER_DATA` を変えて起動しているときは、`setup-hook` にも同じ値を付けて実行します
- 外すときは `npm run setup-hook -- --remove --run` です
- このリポジトリで `claude` を起動して `/setup-hook` と打つと、Claude Code が 1〜2 の手順を進めます
- 手で登録するときは、設定画面の「承認」に出ているコマンドを `hooks.PermissionRequest` に `{ "hooks": [{ "type": "command", "command": "<コマンド>" }] }` の形で足します

設定画面の「承認」で変えられるのは次のものです。この設定はサーバーのデータ用ディレクトリの `settings.json` に保存します。

| 項目 | 既定 | 内容 |
|---|---|---|
| hook から届いた確認を受け付ける | オフ | オフのときは hook に何も返さず、ターミナルにいつものダイアログが出ます。モデルも呼びません |
| 自動で許可する | オフ | オフのときは、すべてカードに出して人が答えます |
| 確認の中身を調べるモデル | `haiku` | `claude --model` に渡す名前 |
| 人に回す条件 | 下の表 | 条件ごとにオン・オフできます。自動で許可するときだけ使います |

人に回す条件は次のとおりです。モデルが判定に失敗したものは、条件によらず人に回します。

| 決め方 | 条件 | 既定 |
|---|---|---|
| コマンドの中身 | `git push`、ファイルの削除、GET 以外の `gh api`・HTTP、`gh` での PR・Issue・リポジトリへの書き込み、データベース・BigQuery、SQL の書き込みらしき語、`sudo`・`kill` などのシステムの操作、`terraform`・AWS・Kubernetes の書き換え、パッケージの公開、`ssh` などの接続、権限の変更、`prod`・`production` を含む名前（17 個） | すべてオン |
| つなぐ先 | `~/.claude/settings.json` の `sandbox.network.deniedDomains` にあるホスト | オン |
| モデルの判定 | 手元の外に書き込む、元に戻せない、重い、コマンドに出てくるスクリプトの中身を読めない | オン |
| モデルの判定 | 手元のファイル・コンテナ・ローカルの git を書き換える | オフ |

- モデルの判定は `claude -p` で、何をするか・接続先・読むだけか書き込むか・元に戻せるか・重いか、を調べます。コマンドに出てくる `.py`・`.sh`・`.js` などのファイルは中身も読んで渡します。この呼び出しは hook・CLAUDE.md・ツールを切って動かし、会話ログを残しません
- ビュワーで動かしているセッションの Bash の許可の確認にも、「自動で許可する」がオンなら同じ判定をかけます。hook を登録していなくても動きます。判定に当たらなければ人に聞かずに許可し、当たったものはカードに理由を出します
- 人に回したものは、ビュワーで動かしているセッションの許可の確認と同じく、入力欄の上にカードで出します。カードには要約・接続先・自動で許可しなかった理由・コマンドが載り、「許可」か、理由を添えて「拒否」で答えます
- カードの縁の色は、コマンドの中身かつなぐ先の条件に当たったもの・外に書き込むもの・元に戻せないものが赤、それ以外が黄色です。モデルが調べている間は紫の点線の縁で「AI が確認中」と出し、人の答えを待つものと見分けられるようにします。調べている間も答えられます。条件をオフにしていても、色はこのとおりに付けます
- 開いていないセッションに確認が届くと、一覧に確認待ちの印が付きます。通知をオンにしていれば OS の通知も出て、押すとそのセッションを開きます
- 540 秒答えが無いとき、ビュワーが動いていないときは、hook は何も返さずに終わり、ターミナルにいつものダイアログが出ます。ターミナルで先に答えたときは、ビュワーからカードが消えます
- セッションを読むとき、自動で許可した Bash の行には「AI が自動で許可」、ビュワーで答えたものには「ビュワーで許可」「ビュワーで拒否」の印が付きます。行を開くと、そのときのモデルの要約・接続先・「読むだけ」などのタグが、コマンドの結果の上に出ます。自動で許可したものを見返して、人に回す条件を見直すときに使います
  - hook の入力にはどのツール呼び出しへの確認かを示す ID が無いので、同じセッションで同じコマンドを持ち、判定より前に出た呼び出しのうち一番近いものに印を付けます
  - 記録の中では、自動で許可したものを `intelligence-auto-approve` と書きます
- 判定の結果は設定画面の「承認」と、データ用ディレクトリの `reviews.jsonl` に残ります。サーバーを起動し直しても、チャットの画面の印は `reviews.jsonl` から読み直します。コマンドがそのまま入るので、扱いには気をつけてください
- hook は、データ用ディレクトリの `hook-token` に書いた合言葉をヘッダーに付けてつなぎます。ブラウザからの POST と違い、`Origin` は確かめません

### サブエージェント

- 動いているサブエージェントがあると、入力欄のすぐ上に横並びのカードで出します。説明・種類・使ったツールの数・経過時間・最後に使ったツールが載り、押すとその呼び出しのところでやり取りを開きます
- 左の一覧で、サブエージェントを使ったセッションには「▸ 数」のボタンが付きます。押すとフォルダのように開いて、サブエージェントが始まった順に並びます。動いているものには青い点が付き、終わったものは小さく薄く出ます。動いているものがあれば、ボタンに「動いている数/全体の数」を出します
- 動いているかどうかは、サブエージェントのログの横にある `meta.json` の `finished` で決めます。`finished` が付いていなくても、本体のログにその呼び出しの結果が返っているか、サブエージェントのログが 10 分書かれていなければ、終わったものとして扱います

### ステータスライン

- 入力欄の上に、`~/.claude/settings.json` の `statusLine` のコマンドが出す 1 行を色付きで出します。Claude Code がコマンドに渡すのと同じ形の JSON を、ビュワーが組み立てて渡します
- 会話ログから、モデル・effort・コンテキストの使用量・キャッシュのヒット率・増減した行数・経過時間を埋めます。増減した行数と経過時間は、会話ログに残っている最後の集計の値です
- 5 時間・7 日の使用率と、コンテキストの上限は会話ログに残りません。ビュワーが `claude` を動かしたときに出力から拾い、それ以降はどのセッションにも最後に拾った値を使います。サーバーを起動してから一度も動かしていなければ、その項目はコマンドの出し方しだいで `--` などになります
- 設定画面の「ステータスライン」で、出し方を選べます。Claude Code の設定のコマンドを使う（既定）・ビュワー専用のコマンドを使う・ビュワーの簡易表示・出さない、の 4 つです。この設定はサーバーのデータ用ディレクトリの `settings.json` に保存します
- 簡易表示は、モデル・使用率・コンテキスト・増減した行数を並べた 1 行です。Claude Code の設定を使うことにしていて `statusLine` が無いときも、この 1 行を出します

### 状態の印と通知

- 一覧の各セッションに、今の状態を色の点で出します。色は tmux のタブの色と同じです（紫の「AI が確認中」はビュワーだけの印です）。いくつか当てはまるときは、上にあるものを出します

  | 色 | 状態 |
  |---|---|
  | 赤 `#ff6b68` | 確認待ち（許可の確認や Claude からの質問に答えるのを待っている） |
  | 紫 `#9876aa`（点滅） | AI が確認中（hook で届いた許可の確認を、モデルが調べている。自動で許可できなければ確認待ちになる） |
  | オレンジ `#ffc66d`（点滅） | 作業中 |
  | 緑 `#6a8759` | 返事は書き終えたが、バックグラウンドのサブエージェントが動いている |
  | 青 `#589df6` | 未読の返事がある |

- ビュワーから動かしているセッションは、ビュワーが持っている状態から決めます。ターミナルなど別のプロセスで動いているセッションは、Claude Code が `~/.claude/sessions` に書いている状態（`busy`・`waiting`）から決めます
- 未読は、返事を書き終えたあと開いていないものです。初めて開いたときより前の返事は未読にしません。読んだ位置はブラウザに保存します
- 設定画面の「通知」で OS 通知をオンにすると、返事が来たときと、確認待ちになったとき（ビュワーから動かしているセッションと、hook でビュワーに届いた確認）に OS の通知を出します。画面で見ているセッションでも通知します。一覧から隠したセッションでは通知しません。ビュワーのタブを閉じていると通知は出ません。押すと、そのセッションのその返事を開きます

### キー操作

既定では次のキーで操作できます。左上の「設定」か `?` で開く設定画面（キー操作・送信・通知・ステータスライン・非表示）の「キー操作」に、今の割り当ての一覧と変える欄があります。

| キー | 動き | 使える場所 | 操作名 |
|---|---|---|---|
| `Enter` | 入力欄の内容をセッションに送る | 送信の入力欄 | `composer.send` |
| `Shift+Enter` | 入力欄で改行する | 送信の入力欄 | `composer.newline` |
| `Enter` / `Shift+Enter` | セッション内検索で次・前の一致へ | セッション内検索の欄 | `find.next` / `find.prev` |
| `Mod+F` | セッション内検索へ移る | どこでも | `find.focus` |
| `Escape` | 送信待ちのメッセージを取り消す。送信待ちが無ければ詳細検索を閉じる | どこでも | `composer.cancelSend` / `searchView.close` |
| `Ctrl+@` | 「会話だけ」と「全部」を切り替える | どこでも | `view.toggleConversation` |
| `/` | 検索欄へ移る | 入力欄の外 | `search.focus` |
| `R` | 一覧と表示中のセッションを読み直す | 入力欄の外 | `reload` |
| `?` | 設定画面を開く | 入力欄の外 | `keys.open` |

`Mod` は Mac では `Cmd`、ほかでは `Ctrl` です。キーの無い操作として、`view.conversationOnly`（「会話だけ」にする）・`view.all`（「全部」にする）・`composer.focus`（送信の入力欄へ移る）・`memo.focus`（メモ欄へ移る）・`session.new`（新規チャットを作る）・`runner.interrupt`（作業中の Claude を止める。2 回押す）・`pane.sidebar` / `pane.head` / `pane.memo`（左の一覧・上のヘッダー・右のメモを開閉する）もあります。

設定画面に JSON を書くと、割り当てを変えられます。設定はブラウザに保存します。

```json
{
  "composer.send": ["Mod+Enter"],
  "composer.newline": ["Enter", "Shift+Enter"],
  "+view.toggleConversation": ["Alt+C"],
  "reload": []
}
```

- 操作名にキーの配列を書くと、既定の割り当てを置き換えます。1 つの操作に複数のキーを割り当てられます
- 操作名の先頭に `+` を付けると、既定の割り当てに足します
- 空の配列にすると、その操作のキーを無くせます
- 修飾キーは `Ctrl`・`Alt`・`Shift`・`Cmd`・`Mod` です。`@` や `?` のような記号は、`Shift` を書かなくても配列によらず動きます
- キーの書き方が分からないときは、設定画面の「キーを押して表記を調べる」の欄でキーを押すと表記が出ます
- 日本語入力の変換中に押したキーでは、どの操作もしません

## 気をつけること

- 会話ログにはコマンドの出力や認証まわりの情報がそのまま入っています。サーバーは `127.0.0.1` でだけ待ち受け、`Host` ヘッダーが `127.0.0.1` か `localhost` のときだけ応えます
- POST 1 本で `claude` を起動でき、ステータスラインの設定ではサーバーが動かすシェルのコマンドも書けます。トンネルや LAN 公開などで外から触れる形にはしないでください。ログインの仕組みはありません
- ファイルの絞り込みに入るのは、Read・Edit・Write・Grep・Glob で扱ったファイルです。Bash の `cat` や `sed` で扱ったファイルは、全文検索で探してください
- 本文に `#123` とだけ書かれた Issue 番号は、どのリポジトリのものか決められないので拾いません
- ログの形式は Claude Code のバージョンで変わることがあります
- Windows では動作確認していません。パスを `/` 区切りで扱っている箇所があります
