# claude-log-viewer

Claude Code のセッションを、ブラウザから探して読み、そのまま続きを動かすためのローカルサーバーです。

- **探して読む**：会話ログ（`~/.claude/projects` の JSONL）をまとめて全文検索し、どの Issue・PR・リポジトリ・ファイルを扱ったセッションかで絞り込めます。長いセッションや「あれはどのセッションだったか」を探しやすくなります
- **続きを動かす**：開いたセッションに続きを送ったり、新しいセッションを始めたりできます。Claude からの質問や許可の確認にもブラウザで答えられ、入力欄の上にはターミナルと同じステータスラインが出ます
- **並べて見張る**：返事が来たセッションに未読の印が付き、OS の通知を押すとその返事まで飛べます。作業を眺めながら、次に送るプロンプトをメモ欄に書いておけます

依存パッケージはありません。

## 起動

Node.js 20 以上が必要です（動作確認は Node.js 24）。

```sh
git clone https://github.com/Marco3jp/claude-log-viewer.git
cd claude-log-viewer
npm start
```

http://127.0.0.1:4317/ を開きます。

| 環境変数 | 既定値 | 内容 |
|---|---|---|
| `PORT` | `4317` | 待ち受けるポート |
| `CLAUDE_PROJECTS_DIR` | `~/.claude/projects` | 会話ログを読むディレクトリ |
| `CLAUDE_LOG_VIEWER_DATA` | `~/.local/share/claude-log-viewer` | ブックマーク・メモ・ステータスラインの設定の保存先（`XDG_DATA_HOME` があればその下） |
| `CLAUDE_BIN` | `claude` | 続きを送るときに起動する Claude Code のコマンド |

## できること

### セッションを探す

- 左の検索欄で全文検索します。スペース区切りで AND、`"…"` でフレーズ、先頭に `-` で除外です
- 検索の対象は、ユーザーの発言・Claude の返答・思考・ツールの入力と結果（先頭 4,000 字）・サブエージェントのやり取りです
- 「詳細検索」を開くと、次の条件で絞り込めます。候補には件数が出て、クリックすると条件に加わります
  - リポジトリ（作業ディレクトリの `.git/config` から GitHub の `owner/repo` を出します）
  - Issue・PR（GitHub の URL、`gh pr view 123` などのコマンド、Claude Code が記録した PR のリンクから拾います）
  - 読み書きしたファイル・ディレクトリ（パスの一部で指定し、読んだ・書いたを選べます）
  - 期間、プロジェクト、ブランチ、使ったツール、MCP サーバー、ブックマーク
- 条件は URL に入るので、ブラウザのブックマークでも同じ検索を開き直せます
- `/usage` のようなローカルコマンドだけで Claude の返答が無いセッションは、一覧に出しません。詳細検索の「返答の無いセッションも出す」で出せます

### セッションを読む

- セッションは末尾（一番新しいところ）で開きます。通知から開いたときはその返事、未読があれば前に読んだところより後の最初の行、検索語があれば最初の一致で開きます
- ヘッダーに `claude --resume <id>` のコピーボタン、関わった Issue・PR、読み書きしたファイルの一覧が出ます
- 思考・Bash・ツール・MCP・サブエージェント・システムを、種類ごとに表示・非表示できます
- セッション内検索で、一致した箇所へ前後に移動できます。非表示にしている種類の中の一致は件数だけ出ます
- 右端のメモ欄に、セッションごとのメモを書けます。作業を眺めながら次に送るプロンプトを書いておく場所です。書いた内容は自動で保存し、「入力欄へ」で選択した部分（選択が無ければ全部）を送信の入力欄に写せます
- Claude の返答は Markdown として表示します。表は等幅フォントです
- サブエージェントの呼び出しを開くと、その中のやり取りをその場に展開できます
- 会話ログが書き足されると、2 秒ほどで一覧と表示中のセッションが読み直されます。読んでいた位置は保ち、末尾を見ていたときは末尾に付いていきます。タブが裏にある間は止まり、表に戻したときに読み直します
- ★ でセッションをブックマークできます
- 一覧・ヘッダー・メモは、境目のドラッグで大きさを変えられます。ボタンで畳めて、ダブルクリックで元の大きさに戻ります

### 続きを送る

- セッションの下の入力欄から、そのセッションに続きのメッセージを送れます。既定では `Enter` で送信、`Shift+Enter` で改行で、キー操作の設定で変えられます
- 送信してから Claude に渡すまで、既定では 2 秒待ちます。その間は会話の末尾に仮の吹き出しが出て、「取り消す」か `Esc` で取り消せます。取り消した文面は入力欄に戻ります。待つ秒数は設定画面の「送信」で変えられ、0 にするとすぐ送ります。送ったあとも、会話ログに書かれるまでは「送信済み・反映待ち」の吹き出しを出します
- サーバーがセッションの作業ディレクトリで `claude -p --resume <id>` を起動し、会話ログに書き足された分がそのまま表示されます。プロセスは 10 分使わなければ止まります
- 入力欄の右に、状態（待機中・作業中・確認待ち）と権限モード、「送信」「止める」をいつも出します。「止める」は作業中か確認待ちのときだけ押せて、続けて 2 回押すと、Claude Code で `Esc` を押したときと同じくその回の作業を打ち切ります。会話とプロセスはそのまま残るので、続けて送れます
- 権限モードは、そのセッションをターミナルで最後に使ったときのもの（`auto`・`acceptEdits`・`plan`・`dontAsk`）を引き継ぎます。ビュワーで始めたセッションは、ビュワーで選んだモードを引き継ぎます。`bypassPermissions` は引き継がず、確認を出すモードで動かします
- Claude からの質問（AskUserQuestion）と、ツールや MCP を使う前の許可の確認は、入力欄の上にカードで出ます。選択肢を選ぶ・許可する・理由を添えて拒否する、をそこで答えます。許可の確認には、Bash なら説明とコマンド、Edit なら変更前と変更後のように、ツールごとに中身を分けて出します
- ターミナルなど別のプロセスで開いているセッションには送れません。同じ会話ログに 2 か所から書き込まないようにするためです
- POST はこのビュワーのページから来たもの（`Origin` が `http://127.0.0.1:<PORT>` か `http://localhost:<PORT>`）だけを受けます

### 新しく始める

- 左上の「新規チャット」で、作業ディレクトリ・権限モード・最初のメッセージを入れて新しいセッションを始められます
- 作業ディレクトリの候補には、最近のセッションで使ったディレクトリが出ます。開いているセッションがあれば、その作業ディレクトリが初めから入ります
- 会話ログが書かれ始めると、そのセッションが開きます。そこからは「続きを送る」と同じように使えます

### ステータスライン

- 入力欄の上に、`~/.claude/settings.json` の `statusLine` のコマンドが出す 1 行を色付きで出します。Claude Code がコマンドに渡すのと同じ形の JSON を、ビュワーが組み立てて渡します
- 会話ログから、モデル・effort・コンテキストの使用量・キャッシュのヒット率・増減した行数・経過時間を埋めます。増減した行数と経過時間は、会話ログに残っている最後の集計の値です
- 5 時間・7 日の使用率と、コンテキストの上限は会話ログに残りません。ビュワーが `claude` を動かしたときに出力から拾い、それ以降はどのセッションにも最後に拾った値を使います。サーバーを起動してから一度も動かしていなければ、その項目はコマンドの出し方しだいで `--` などになります
- 設定画面の「ステータスライン」で、出し方を選べます。Claude Code の設定のコマンドを使う（既定）・ビュワー専用のコマンドを使う・ビュワーの簡易表示・出さない、の 4 つです。この設定はサーバーのデータ用ディレクトリの `settings.json` に保存します
- 簡易表示は、モデル・使用率・コンテキスト・増減した行数を並べた 1 行です。Claude Code の設定を使うことにしていて `statusLine` が無いときも、この 1 行を出します

### 未読と通知

- 返事を書き終えたセッションには、一覧で青い点が付きます。初めて開いたときより前の返事は未読にしません。読んだ位置はブラウザに保存します
- Claude が確認を待っているセッションには「確認待ち」の印が付きます（ビュワーから動かしているセッションだけ）
- 設定画面の「通知」で OS 通知をオンにすると、表示中でないセッションに返事が来たときと、確認待ちになったときに OS の通知を出します。押すと、そのセッションのその返事を開きます

### キー操作

既定では次のキーで操作できます。左上の「設定」か `?` で開く設定画面（キー操作・送信・通知・ステータスライン）の「キー操作」に、今の割り当ての一覧と変える欄があります。

| キー | 動き | 使える場所 | 操作名 |
|---|---|---|---|
| `Enter` | 入力欄の内容をセッションに送る | 送信の入力欄 | `composer.send` |
| `Shift+Enter` | 入力欄で改行する | 送信の入力欄 | `composer.newline` |
| `Enter` / `Shift+Enter` | セッション内検索で次・前の一致へ | セッション内検索の欄 | `find.next` / `find.prev` |
| `Mod+F` | セッション内検索へ移る | どこでも | `find.focus` |
| `Escape` | 送信待ちのメッセージを取り消す。送信待ちが無ければ詳細検索を閉じる | どこでも | `composer.cancelSend` / `searchView.close` |
| `Ctrl+@` | 「会話だけ」と「全部」を切り替える | どこでも | `view.toggleConversation` |
| `/` | 検索欄へ移る | 入力欄の外 | `search.focus` |
| `R` | 一覧と表示中のセッションを読み直す | 入力欄の外 | `reload` |
| `?` | 設定画面を開く | 入力欄の外 | `keys.open` |

`Mod` は Mac では `Cmd`、ほかでは `Ctrl` です。キーの無い操作として、`view.conversationOnly`（「会話だけ」にする）・`view.all`（「全部」にする）・`composer.focus`（送信の入力欄へ移る）・`memo.focus`（メモ欄へ移る）・`session.new`（新規チャットを作る）・`runner.interrupt`（作業中の Claude を止める。2 回押す）・`pane.sidebar` / `pane.head` / `pane.memo`（左の一覧・上のヘッダー・右のメモを開閉する）もあります。

設定画面に JSON を書くと、割り当てを変えられます。設定はブラウザに保存します。

```json
{
  "composer.send": ["Mod+Enter"],
  "composer.newline": ["Enter", "Shift+Enter"],
  "+view.toggleConversation": ["Alt+C"],
  "reload": []
}
```

- 操作名にキーの配列を書くと、既定の割り当てを置き換えます。1 つの操作に複数のキーを割り当てられます
- 操作名の先頭に `+` を付けると、既定の割り当てに足します
- 空の配列にすると、その操作のキーを無くせます
- 修飾キーは `Ctrl`・`Alt`・`Shift`・`Cmd`・`Mod` です。`@` や `?` のような記号は、`Shift` を書かなくても配列によらず動きます
- キーの書き方が分からないときは、設定画面の「キーを押して表記を調べる」の欄でキーを押すと表記が出ます
- 日本語入力の変換中に押したキーでは、どの操作もしません

## 気をつけること

- 会話ログにはコマンドの出力や認証まわりの情報がそのまま入っています。サーバーは `127.0.0.1` でだけ待ち受け、`Host` ヘッダーが `127.0.0.1` か `localhost` のときだけ応えます
- POST 1 本で `claude` を起動でき、ステータスラインの設定ではサーバーが動かすシェルのコマンドも書けます。トンネルや LAN 公開などで外から触れる形にはしないでください。ログインの仕組みはありません
- ファイルの絞り込みに入るのは、Read・Edit・Write・Grep・Glob で扱ったファイルです。Bash の `cat` や `sed` で扱ったファイルは、全文検索で探してください
- 本文に `#123` とだけ書かれた Issue 番号は、どのリポジトリのものか決められないので拾いません
- ログの形式は Claude Code のバージョンで変わることがあります
- Windows では動作確認していません。パスを `/` 区切りで扱っている箇所があります
